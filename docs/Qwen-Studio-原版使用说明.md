# Qwen Studio · 使用说明

本机（RTX 4060 Laptop 8G）上的 Qwen-Image-2.1 出图程序。**双击桌面上的「Qwen Studio」就能用**。

---

## 一分钟上手

1. 双击桌面 **Qwen Studio** 图标 → 窗口立刻出现（如果绘图内核还没起来，页面上会显示「正在启动绘图内核…（已 N 秒）」，等十几秒就好）。
2. 在「你想画什么？」里写一句话，比如 `一只戴墨镜的柴犬趴在沙滩上，夕阳，胶片质感`。
3. 选**一次画几张**（默认 4 张），点底部 **生成**。8 步 LoRA 下 1024×1024 每张约 14 秒，4 张约 56 秒。
4. 想改图：把一张图片**拖进虚线框**（或点它选文件），再写一句话，点生成。放图 = 改图，不放 = 新画。
   - 改图时要说清「改哪里」，例如 `把背景换成纯绿色，人物姿势、脸、衣服保持不变`。参考图会额外占用一部分计算，**同样步数下耗时约为新画的 2 倍**（1024 图 40 步：改图约 150 秒，新画约 60 秒）；嫌慢就用「快」预设（8 步）。

就这样。窗口里没有别的东西需要动。

**抽卡**：同一句话一次出 2–4 张，挑一张最顺眼的 —— 这就是「抽卡」。只换种子不换提示词最便宜（不用重新编码提示词）。

## 界面上的东西

| 位置 | 作用 |
| --- | --- |
| 顶部圆点 | 绿 = 内核就绪；琥珀 + 「正在启动内核…」= 正在拉 ComfyUI |
| 顶部「显存 x 空闲 / 8.0 GB」 | 实时状态。生成时数字会掉到 2 GB 以下，正常 |
| **一次画几张** | 1 / 2 / 4 / 8 张。**8G 显存建议不超过 4 张**（8 张会很吃显存） |
| 「打开输出文件夹」 | 在资源管理器里打开出图所在的文件夹（默认 `E:\ComfyUI_windows_portable\ComfyUI\output\`，**可以改**，见下） |
| 「输出位置…」 | 弹一个文件夹选择框，**换一个地方存以后出的图**（见下面「输出位置可以改」） |
| 「环境自检」 | 检查服务、模型文件、工作流是否正常，**不占用显卡**，几秒出结果 |
| **历史**（结果区） | 每次生成一张卡片，**最新的在最前面，一页 10 条**，底部可翻页、可改每页 10/20/50/全部；**别处删过的记录会自动同步掉** |
| 「高级参数」 | 不展开就是用默认值。**不看完全没问题** |

小按钮：「示例描述」自动填一句示例；「重画这张」用刚才的种子和参数重跑；右上「清空历史」删掉全部记录。
快捷键：**Ctrl+Enter** 直接出图。

**关掉窗口再打开，历史还在**（记在 `app\history.json`，图片直接从输出目录读，不占显卡）。

## 输出位置可以改

默认所有出图都落在 ComfyUI 自己的输出目录 `E:\ComfyUI_windows_portable\ComfyUI\output\`。想换个地方（比如挪到数据盘、或者放到一个同步文件夹里）：

1. 点顶部的 **「输出位置…」**，在弹出的文件夹选择框里挑一个目录，确定。
2. 换完之后，**以后新出的图会直接存到新地方**（ComfyUI 写完立刻搬过去，原目录不留副本）。顶部会多出一条浅蓝提示条写着「出的图存在：…」，后面跟一个「换一个地方」按钮，随时能再改。
3. **老图不会搬家**，但历史里照样能看、能拿来接着改、能一键定位到它原来所在的文件夹 —— 程序记的是每张图的绝对路径。

想改回默认：再点一次「输出位置…」，选回 `E:\ComfyUI_windows_portable\ComfyUI\output` 就行（提示条会自动消失）。

设置存在 `app\settings.json` 里，重装/换电脑时把这个文件一起带走即可。

## 大图预览：左右翻页

点任意一张图上的 **「看大图」**（或直接点图）进入全屏预览，此时：

- 两侧出现 **‹ ›** 按钮，点它切上一张 / 下一张；
- 键盘 **← →** 同样可以切，**Esc** 关闭；
- 底部有 **「第 i / n 张 · 第几次 · 宽×高 · 文件名」** 的说明，切到哪张一目了然；
- **翻页范围是整个历史上所有还在的图**（不只是当前这一批），按界面上的顺序走，到头会绕回第一张。

## 历史：看以前的图、拿它接着改、删掉它

每张卡片上有：**第几次 / 时间 / seed / 步数 / 耗时**，下面依次是**参考图**（当时喂进去的原图）、**当时的提示词**、**出图**，以及四个按钮。

| 按钮 | 作用 |
| --- | --- |
| **编辑（用这张改）** | **这张图变成参考图，提示词和参数一起回填到输入框**，改完直接点生成 —— 这就是「以图生图」接着改 |
| 复制图片 | 图片进剪贴板，可以直接粘到聊天窗口 |
| 在文件夹中显示 | 在资源管理器里定位到原图 |
| 看大图 | 全屏预览，**可以用 ‹ › 或 ← → 左右翻着看**（Esc 退出） |
| 删除这张 | 把这**一张**从历史里去掉 |
| 删掉这条记录 | 没有图可看的旧记录，只删记录 |

**删除只删记录、不删图片文件** —— 想连文件一起删，先勾上右上角那个 **「连图片文件一起删」** 复选框（勾了之后确认框里会明确写「图片文件也会一起删掉，不能恢复」）。这个设计是故意的：这个项目踩过一次「图莫名其妙没了」的坑，删文件必须是你亲手勾的动作。

> 卡片变成橙色的「这一批的图片文件已经不在了」= 图片文件被别的东西删过（历史里还留着提示词和参数，但没法拿它当参考图）。点「删掉这条记录」可以清理掉。

## 「高级参数」里有什么（可选）

展开后最上面是**六档预设**，点一下就把下面所有参数调好（放参考图时预设会顺手把「输出画幅」切成「自定义宽×高」，这样它的尺寸数字才真的生效；只有「细节增强」不碰尺寸，详见下）：

| 预设 | 参数 | 耗时 | 用途 |
| --- | --- | --- | --- |
| 快 | 8 步 + LoRA | ~22 秒 | 试想法、批量探路 |
| 质量优先 | 25 步 | ~43 秒 | **日常推荐**，质感明显好于 8 步 |
| 最精细 | 40 步 | ~70 秒 | 要细节时用 |
| 2K 大图 | 25 步 / 2048×2048 | **~4.6 分钟** | 显存几乎打满（7.6/8.0 GB），出图前别开别的大型软件 |
| 2K 精细 | 40 步 / 2048×2048 | 约 7–11 分钟 | 只出横幅大片时用 |
| **细节增强** | 25 步 + 关 LoRA + `euler/simple` + **cfg 4（让负面词真正生效）** | **改图约 3.3 分钟** | 下半身、布料、鞋子这类小细节不真实时用，见下面的说明 |

**「细节增强」为什么能提细节**：靠的是**把 cfg 抬到 4，让负面提示词真正开始工作**（默认 cfg=1 时负面词是完全无效的）。**它不会替你往负面框里填任何词** —— 负面提示词默认留空，写什么由你自己决定；出图尺寸和参考图像素都不动。

轮到你填的时候，想省事可以直接抄这段（英文词表，逗号分隔）：

```text
blurry, low detail, smeared, plastic, cropped legs, missing feet, extra limbs, deformed hands, low quality
```

实测（同一张 1024×1536 全身参考图 + 同提示词 + 关 LoRA + `euler/simple`，用「固定腿窗口 + 统一网格」这套与背景无关的指标量，缩略图会骗人）：

| 档 | 配置 | 出图 | 耗时 | 下半身 |
| --- | --- | --- | --- | --- |
| 基线 | res 1024 / cfg 1 / 12 步 | 832×1248 | 58.8 秒 | 布料被抹平，看不到斜纹缝线 |
| **细节增强** | cfg 4 / 25 步 | 832×1248 | **199.7 秒** | **腿部纹理 ×2.09、缝带反差 ×2.14、结构 ×2.44**，是唯一能看出斜纹缝线和膝盖椭圆的一档 |
| 对照 | cfg 1 / 25 步（同种子） | 832×1248 | 105.5 秒 | ×0.945 ⇒ **光加步数没用** |
| 参考图吃 2K | res 2048 / cfg 1 / 12 步 | 1664×2496 | 426.5 秒（×7.3） | 画面大 4 倍，也能救回结构，但太慢，没做成预设 || 参考图吃 1.5K | res 1536 / 25 步 | 1248×1888 | 358.2 秒（×6.1） | 指标反而更差，还会把腿拉长、鞋子挤偏 ⇒ 不采用 |

三条反直觉的结论：**① 加步数不是杠杆**（12 步 → 25 步几乎不涨细节，只涨时间）；**② 采样器别乱换** —— `dpmpp_2m/karras` 在本链路上明显更差（腿发丝状、鞋子带光晕），官方 `euler/simple` 才是最优；**③ 真正有效的是让负面词生效**。**它故意不改出图尺寸**：想让画面也更大，先点「细节增强」再点「2K 大图」。

下面六组参数：

- **速度与质量**：步数、引导强度 cfg、采样器、调度器、降噪。官方 `euler` + `simple` 最稳（实测换 `dpmpp_2m/karras` 更差，腿发丝状、鞋子带光晕，别换）。**cfg 默认 1.0，此时负面提示词完全不生效** —— 想用负面词就得把它抬到 3–5，画面会变"硬"、背景可能出现渐变暗角，这是正常代价。
- **尺寸与数量**：宽、高、**输出画幅**（见下一节）、参考图缩放边长，以及七个常用比例快捷键（1:1 / 3:2 / 16:9 …）。「一次画几张」在主界面上那排按钮里。
- **随机种子**：默认「每次随机」；取消勾选填固定种子就能复现同一张图（每张结果卡片上会显示它用的种子）。
- **LoRA 加速**：勾上后 **必须把步数改成 8**，否则图会糊。这是把 25 步压到 8 步还能看的关键。
- **负面提示词**：分两栏 ——「**系统级负面提示词**」（填一次、每张图自动带上）和「不想要的内容」（这一张专用的）。**两栏默认都是空的，程序不会替你填任何词**；**两栏加起来只有 cfg 大于 1 时才真正生效**。默认 cfg=1，写在这里也没用。详见下面「系统级负面提示词」。
- **模型与显存**：换模型文件、编码器放 CPU 还是 GPU、Cache 设备与精度。一般不用碰；**改图报 `aimdo memory compile error` 时把「Cache 设备」改成 `cpu`**。

## 系统级负面提示词（填一次，以后每张图都自动带上）

「高级参数 → 负面提示词」里现在是**两栏**：

| 栏目 | 作用 |
| --- | --- |
| **系统级负面提示词（一直生效）** | 填在这里的词**每一张图都自动带上**，不用每次重打。适合放那些「任何图都不想要」的通用词 |
| 不想要的内容（cfg = 1 时无效） | 这一张专用的负面词，跟以前一样 |

发出去的时候两栏会**自动拼起来**：系统级那段排在**前面**，你自己写的那段接在后面，中间用 `, ` 隔开。框下面那行灰字「本次实际发送：…」就是这次真正送给绘图内核的完整内容，随时可以核对。

- **改完自动保存，关掉程序下次打开还在**（存在 `app\settings.json` 的 `sys_negative` 字段）。打完字停 0.7 秒就存，鼠标点走也会立刻存；存好右下角弹一句「系统级负面词已保存（N 字，一直生效）」。
- **留空 = 关掉这个功能**，跟没加过一样。
- 多打的逗号和空格会自动去掉，不会拼出 `,, ` 这种。
- **「编辑（用这张改）」回填旧图参数时不会动它** —— 拿旧图接着改，不会把你设好的系统级词覆盖掉。
- 命令行入口（`draw.bat`、`qwen.py`）也自动带上这段词，不只是界面上生效。

> ⚠️ 系统级负面词**同样受 cfg 限制**：默认 cfg=1 时，负面词（包括这段）**完全不生效**。想让它真的起作用，得把 cfg 抬到 3–5 —— 点「细节增强」预设最省事，它顺手把 cfg 设成 4。

## 改图时怎么定出图的大小（「输出画幅」）

只放参考图、什么都不改时，**出图比例和像素完全由第一张参考图决定**（竖屏参考图 → 竖屏出图），下面「宽/高」两个框是灰的、不起作用。这是模型官方设计：编辑任务里画布跟着参考图走，编辑才不会漂。

想自己定出图大小，就在「高级参数 → 尺寸与数量 → 输出画幅」里选：

| 选项 | 出图大小 | 什么时候用 |
| --- | --- | --- |
| 跟随参考图（默认） | 由第一张参考图决定 | 单纯改图 |
| 按原图比例·原尺寸 | 等于参考图原始像素（32 的倍数） | 不想被缩放 |
| 按原图比例·放大倍数 | ×0.5 / ×1 / ×1.5 / ×2 / ×3 / ×4 | 保持构图，放大或缩小出图 |
| 按原图比例·指定像素 | 按面积算（1MP / 2.25MP / 4MP …），比例不变 | 想要具体像素量 |
| 指定比例 + 像素 | 比例 + 百万像素自己选（1:1、9:16、16:9 …） | **竖屏参考图出方形/横屏** |
| 自定义宽×高（可扩图） | 严格等于你填的「宽 × 高」 | **扩图、精确 2K** |

要点：

1. **「参考图缩放边长 resolution」不是出图尺寸**，它只是让模型看清楚参考图的面积预算（默认 1024²）。出图尺寸看上面的「输出画幅」。
2. **想稳定出 2048×2048**：输出画幅选「自定义宽×高」，宽高都填 2048（或者直接点顶部「2K 大图」预设，它会自动切到这里）。
3. **扩图是把双刃剑**：画布和参考图差得越远，原内容漂移越多。实测 832×1216 竖屏参考图出 2048×2048 时，模型会重新安排构图（参考图里的主体可能被摆成画面里的一个元素）。**先用 4 步试一张看构图，确定了再上 25/40 步正式跑**（4 步那张只要几十秒，40 步 2K 要十分钟）。
4. **速度参考**（832×1216 参考图，2048×2048 画布，关 LoRA）：4 步约 43 秒、40 步约 10.8 分钟，显存几乎打满（采样到只剩几十 MB 空闲）。**2K 出图前把别的吃显存的程序关掉**，否则容易 CUDA out of memory。

## 三个必须知道的事实

1. **换种子比换提示词便宜得多。** 文本编码器（6 GB）和画图模型（7.2 GB）加起来超过 8 GB 显存，只能轮流上卡。改了提示词要重新编码（慢），只改种子不用。
2. **一次出多张比连着出多张划算。** 想挑图就把「一次画几张」调成 2–4，共享一次编码。
3. **许可证是 Qwen Research License，非商用。** 商用需向 `model-business@notice.qwencloud.com` 申请。上一代 Qwen-Image 1.0 虽然是 Apache-2.0 可商用，但 20B 在这张 8G 卡上跑不动。
4. **改图（放了参考图）比新画贵。** 参考图在模型里当作额外的视觉输入参与计算，同样步数下耗时约 2 倍。要快速试想法，先 8 步。

## 出问题了怎么办

| 现象 | 处理 |
| --- | --- |
| 双击图标没反应 | 等 20 秒。还不行就打开「环境自检」看报错——自检会指出是服务没起来还是模型文件有问题 |
| 窗口显示「正在启动绘图内核…」很久 | 首次加载 7 GB 权重约 20–40 秒。超过 2 分钟还不动就点旁边的「重新启动内核」 |
| 窗口白屏 / 显示「拒绝连接」 | 关掉窗口，重新双击图标。程序会自动把后端重新拉起来 |
| 生成时报 `aimdo memory compile error` | 高级参数 → 模型与显存 → 「Cache 设备」改成 `cpu` |
| 嫌慢 | 换「快」预设（每张约 14 秒）；或先用 8 步试想法，定下来再切 25 步重跑 |
| 改图好像没参考原图 | 描述里写清「改什么、保留什么」，并适当提高步数（25 步以上）。参考图缩放边长太小时影响也小，可在高级参数里调大 |
| 改图出图比例不是我要的 / 设了 2K 却只有 1280 | 「输出画幅」在「跟随参考图」，此时出图尺寸由第一张参考图决定。换成「自定义宽×高」填 2048×2048，或点顶部「2K 大图」预设 |
| 显存不够 / 报 CUDA out of memory | 关掉别的吃显存的软件；或把「一次画几张」降到 1–2、尺寸降到 768×768；2K 尤其吃显存 |
| 顶部没有版本号 / 「清空历史」清完列表还在、「每页条数」选了没反应 | 你看的是一个**没自动刷新的旧页面**。现在的版本会自动发现并重载，头部那行会显示 `ui xxxxxxxx` 的编号；实在不放心就关掉窗口重新打开。 |
| 点了「输出位置…」没反应 | 文件夹选择框可能开在别的窗口后面，用 Alt+Tab 找一下。它会等你 5 分钟。 |
| 系统级负面词改了，出图却没变化 | 负面词是跟着 cfg 走的 —— **默认 cfg=1 时一律不生效**（系统级那段也一样）。把 cfg 抬到 3–5，或直接点「细节增强」预设。 |
| 两个负面词框都是空的，是不是丢了 | 不是：**程序从来不替你填负面词**，默认就是空的。想填什么自己写（`app\settings.json` 里只记「系统级」那一栏，只要填过就不会丢）。 |
| 点了「细节增强」，负面提示词框还是空的 | 故意的：这一档只改 cfg / 步数 / 采样器，负面词留给你自己填（上面有一段可以直接抄）。 |
| 桌面图标变成一张空白纸 / 看不见了 | 快捷方式本身没坏，多半是 Windows 在重建图标缓存时来不及画。在桌面按 **F5** 刷新一下，或稍等 1–2 分钟。（2026/9/29 已把图标换成自带的彩色图标 `app\qwen-studio.ico`，不再用系统里那个很淡的通用图标） |
| 下半身 / 手 / 鞋子细节不真实 | 先点「细节增强」预设（见上）：它把 cfg 抬到 4、让负面词真正生效，腿部纹理实测 ×2 以上，约 3.3 分钟。还不行就分两遍走：第一遍正常出图，把结果当参考图再送一遍，提示词只写「保持人物服装姿势不变，锐化面料纹理、缝线、鞋带」。要更大的画面再加「2K 大图」 |
| 想彻底重启 | 点右上角「退出」，再重新双击图标（内核没在跑时程序会自己拉起来） |

## 技术底座（出问题时给懂行的人看）

- ComfyUI 0.37.0 便携版，PyTorch **2.13.0+cu130**，NVIDIA 驱动 **617.14**（cu130 要求 ≥580）。
- 模型：INT8 ConvRot DiT（7.26 GB）+ W4A8 文本编码器（6.31 GB）+ BF16 VAE（0.68 GB）+ Pruna 8 步 LoRA。
- 采样：`euler` / `simple` / cfg 1.0；文本编码走 `TextEncodeQwenImage21`，缓存策略走 `QwenImage21Cache`。
- 链路：Edge `--app` 模式当窗口外壳 → 本地 Python 服务（127.0.0.1:8801）→ ComfyUI API（127.0.0.1:8188）。
